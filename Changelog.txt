fastebaysearch 0.6.2

Fix severity and upgrade notes: https://github.com/Rakki1/fastebaysearch/releases/tag/v0.6.2

- Include fixed-price listings and auctions by default, configurable with ebay_buying_options.
- Display current auction bids and distinguish unavailable prices from zero prices.
- Search newest listings first and report the 10,000-result cutoff as an incomplete run.
- Preserve successful pages and searches when other requests fail or hit a rate limit.
- Retry transient search failures twice and share one OAuth refresh across concurrent 401 responses.
- Reject queries exceeding 100 characters before any API/database access; never silently drop exclusions.
- Add a persistent HTML delivery queue with atomic report files, retry support and concurrent-run protection.
- Add the HTML queue without re-enqueuing existing history; close SQLite connections and keep schema upgrades transactional.
- Report search completeness in HTML, email and Telegram summaries, with nonzero exit codes on failures.
- Fix Telegram exception handling and prevent token-bearing URLs from appearing in error logs.
- Show clean-search report truncation explicitly; clean search still does not access the database.
- Extend API budget estimates with retry allowances and separate OAuth call counts.
- Add regression coverage for collector queries, partial searches, retries, migrations and notification delivery.

fastebayseach 0.6.1

- Changed ebay offset maximum to 9999.
- Added --estimate-api-budget. The output shows the estimated API calls per run, possible runs per day and a recommended cron interval.
- Added optional local HTML report output as an independent notification channel.
- Added --clean-search for running an eBay search without reading from or writing to the database.
- Added Telegram retry claim tracking to reduce duplicate messages after timeout errors.
- Fixed eBay item report links to use the listing marketplace domain instead of the API returned marketplace URL.
- Fixed Telegram header retry accounting, eBay rate-limit task cancellation and invalid JSON config handling.
- Improved pending notification query performance with partial SQLite indexes.
- Added rotating log files with configurable max log size via log_max_size_mb.
- Added and expanded tests for API budget estimation, CLI modes, HTML reports, Telegram retry handling and logging setup.
- Removed unused code.

fastebaysearch 0.6.0

- Refactored all code to make it easier to maintain.
- Reworked result claiming and notification flow. New results are now claimed in SQLite before notifications are sent, preventing duplicate notification races.
- Added per-channel notification retry state for email and Telegram.
- Improved SQLite locking and schema handling with BEGIN IMMEDIATE locks, idempotent schema creation and safer history run tracking.
- Added exchange rate caching to SQLite with configurable TTL.
- Improved eBay API robustness, token response validation and aiohttp session reuse.
- Added api_concurrency, telegram_send_mode and stricter config validation.
- Improved SMTP handling with proper STARTTLS SSL context and optional authentication.
- Made OAuth token cache writes atomic and tightened token file permissions where supported.
- Improved query generation, config path handling and database path restrictions.
- Improved date parsing performance with from iso format fallback logic.
- Reduced broad exception handling and replaced several generic catch blocks with specific exception types.
- Made email and Telegram notifiers return success status and injectable for tests.
- Added tests for notification retry behavior, history updates, config validation and notifier injection.
- Added pytest.ini and .gitignore rules to keep pytest temp/cache directories out of test collection and version control.
- Removed obsolete legacy database migration support and unused legacy conversion code.
